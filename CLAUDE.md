# CLAUDE.md

Source for **noisypigeon.com**, a personal blog. Static site, built with
[Zola](https://www.getzola.org/). Split out of `noisypigeon/noisypigeon` on 2026-10-12
(ADR-0159); the scaffolding in this file arrived with NPC-0000.

This document describes the tree as it is now. Edit it in place when the tree changes — it is not
a history. `CHANGELOG.md` is the history.

## Layout

```
CHANGELOG.md                    generated by CI -- see "Changelog" below
.mise.toml                      zola version, build tasks, theme-fetch hook
noisypigeon.com/
  fetch-templates.sh            clones pigeon.dev into .templates-src/
  src/
    config.toml                 the only build config
    content/
      _index.md                 homepage
      posts/                    54 posts, NNNN-slug.md
      pages/                    about.md, lineage.md
      changelog/                published changelog digests
    static/
      manifest.json, robots.txt
      assets/images/posts/<post-slug>/
      assets/images/site/       avatar, favicons, social preview
.github/workflows/              thin callers into pigeon.dev -- see "CI"
```

`src/themes/`, `src/public/`, and `/.templates-src/` are generated and gitignored. Nothing
commits into them.

## Where the dependencies are

**Nothing is vendored in this repo.** Both dependencies live elsewhere, which is the single most
important thing to know before changing anything:

| What | Where | How it gets here |
| --- | --- | --- |
| Zola 0.23.6 | pinned in `.mise.toml` | `mise install` |
| The theme (`zola-site`) | `noisypigeon/pigeon.dev`, at `templates/zola-site` | `noisypigeon.com/fetch-templates.sh` clones pigeon.dev to `/.templates-src/`; that clone's `resolve-theme.sh` then links `src/themes/zola-site` |
| CI job bodies | `noisypigeon/pigeon.dev`, at `.github/workflows/` | reusable workflows, called `@main` |

`resolve-theme.sh` reads `[extra] theme_version` from `src/config.toml` to decide what to link.
`"main"` (the current value) is a live symlink into the pigeon.dev clone, so **theme changes show
up locally the moment you re-run a build task** — convenient, and also means the deployed theme
tracks pigeon.dev's default branch. A concrete version instead materializes the
`templates/zola-site/v<version>` tag.

To change the theme, send a PR to `noisypigeon/pigeon.dev`. Nothing in this repo can do it.

## Working on it

```sh
mise install          # installs zola; the postinstall hook fetches the theme
mise run blog-serve   # http://127.0.0.1:1111
mise run blog-build   # writes noisypigeon.com/src/public/
```

Both tasks re-fetch the theme and re-resolve it first, so they are safe to run after a pigeon.dev
change. `git status` should be clean after a build; if it isn't, `.gitignore` is missing a
generated path.

## Content conventions

Front matter is **TOML** (`+++`), not YAML:

```toml
+++
title = "cmd+a, zip, scatter"
date = 2026-02-07T07:14:40+00:00          # RFC 3339, with offset
slug = "cmda-zip-scatter"
description = "One sentence. Used for the listing and for social cards."
# aliases = ["pages/names"]               # optional, for moved URLs

[taxonomies]
tags = ["personal-essays", "data-hoarding"]

[extra]
og_image = "/assets/images/posts/cmda-zip-scatter/img_2722.jpg"
+++
```

- **Posts** are `content/posts/NNNN-slug.md`, numbered in publication order. `slug` in the front
  matter is what the URL uses; the `NNNN-` prefix only orders the directory.
- **Tags** come from an existing vocabulary — `personal-essays`, `career`,
  `software-engineering`, `hardware-and-builds`, `travel`, `data-hoarding`,
  `press-and-interviews`, `photography`, `identity-and-transition`. Reuse one rather than coining
  a near-duplicate; each one is a published taxonomy page.
- **Images** go to `static/assets/images/posts/<post-slug>/`, filenames lowercased and sanitized,
  referenced as `/assets/images/posts/<post-slug>/<file>`.
- **Archive posts** (anything predating this site) carry the standard banner:
  `> 📖 **Note**: This post is from the archives. It may reflect outdated views or a [previous name](/pages/names/).`
- Post bodies contain raw `<figure class="attachment …">` HTML, a Jekyll-era carryover. Match the
  surrounding markup when editing an old post rather than modernizing it in passing.
- `content/changelog/` has two naming schemes on purpose: `0001-`–`0004-` are hand-written
  platform-migration announcements, and `YYYY-MM-DD-changelog.md` digests are written by CI.
  Don't hand-edit the dated ones.

## Changelog

`CHANGELOG.md` is **generated — do not hand-edit it.** On every merged PR touching
`noisypigeon.com/src/**`, CI prepends the PR body verbatim and appends a line to that day's
digest under `content/changelog/`.

Two consequences:

1. **The PR body is published copy.** Write it for a reader of the blog, not for a reviewer.
2. **The first five lines of `CHANGELOG.md` are load-bearing.** CI splices entries with
   `head -n 5` / `tail -n +6`. Reflow that header and entries start landing in the middle of
   prose.

Entries before 2026-10-13 describe monorepo concerns (Terragrunt, `workloads/`, `root.hcl`) and
link to `noisypigeon/noisypigeon` PRs. That is inherited history, deliberately left as-is.

## CI

Both workflows are thin callers; the job bodies are in pigeon.dev, so **that is where CI behavior
is defined.** These files hold only what cannot live in another repo — triggers, permissions,
concurrency, path filters, and the merged-only gate.

- `noisypigeon-com-pages.yml` → `zola-site-pages.yml`. Builds and deploys to GitHub Pages on
  pushes to `main` under `noisypigeon.com/src/**`.
- `blog-changelog.yml` → pigeon.dev's `blog-changelog.yml`. Writes the changelog and digest on a
  merged PR, then dispatches the Pages deploy. Passes `changelog_path: CHANGELOG.md` and omits
  `root_changelog_tag`, which opts out of the cross-workload rollup this repo has no use for
  (NPC-0000).

## Commits and PRs

[Conventional Commits](https://www.conventionalcommits.org/), with an optional scope and the PR
number appended by squash merge: `feat(blog): add a post (#12)`. Tooling assumes the prefix — the
digest-title generator strips `^[a-z]+(\([^)]+\))?: ` — so it is not merely style.

## Decision records

ADRs for this repo live in **`noisypigeon/pigeon.dev`, under
[`adr/noisypigeon.com/`](https://github.com/noisypigeon/pigeon.dev/tree/main/adr/noisypigeon.com)**,
not here. Read them before changing the build, the CI wiring, or the repo layout; if a change
would contradict one, write a new ADR or update the old one's `Status` rather than silently
diverging.

**Filing one:**

- Filename `NPC-NNNN-<kebab-slug>.md`, in `adr/noisypigeon.com/`. Next number is the highest in
  that directory **+1** — check it, since nothing computes it for you.
- The `NPC-` prefix matters. `adr/infrastructure/` is a separate corpus with its own sequence
  (`0031`–`0159`) that cross-cites by bare `ADR-NNNN`; the prefix keeps the two unambiguous.
  Cite blog ADRs as `NPC-NNNN` and infrastructure ones as `ADR-NNNN`.
- `adr-new.sh` in the monorepo is hardcoded to `adr/infrastructure` and **cannot create these**.
  Write the file by hand.
- Nothing indexes ADRs — there is no registry to update. Branch `adr/npc-NNNN-<slug>`, commit
  `docs(npc-NNNN): <title>`.
- Genuinely deferred `## Out of scope` items get an issue filed against `noisypigeon/noisypigeon`
  via `mise run adr-issue` from a monorepo checkout (ADR-0031). Permanent design boundaries do
  not.

**Template** — no YAML front matter; an H1, three bullets, then the sections:

```markdown
# NPC-NNNN: <title>

- **Author**: Willow Finch/Graysen ([@noisypigeon](https://github.com/noisypigeon)).
- **Date**: YYYY-MM-DD.
- **Status**: Accepted.

## Context

## Decision

## Consequences

## Out of scope
```

`## Verification` is optional and goes last, for ADRs whose outcome is checkable.

`Status` is one of: `Accepted.`, `Exploration.` (a design spike recording a direction and its open
questions, not something landed), `Superseded by [NPC-NNNN](NPC-NNNN-slug.md).`, or
`Accepted; superseded in part by [NPC-NNNN](…) (<which part, specifically>).`

House style, worth matching: state findings as facts verified against the live tree rather than
against prior prose; say plainly what a decision reverses; classify every `## Out of scope` bullet
as either a permanent boundary or genuinely deferred; and in `## Consequences`, name concrete
costs rather than restating the benefits.
